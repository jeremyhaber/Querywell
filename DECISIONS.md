# Decisions

Defaults chosen where the brief left room. Each is cheap to revisit unless noted.

| # | Date | Decision | Why |
|---|------|----------|-----|
| 1 | 2026-10-26 | Xcode project generated by **XcodeGen** from `project.yml`; `.xcodeproj` is gitignored and regenerated by `scripts/ci.sh`. | Diffable, merge-friendly project definition; agents can edit YAML safely. Run `xcodegen generate` before opening in Xcode. |
| 2 | 2026-10-26 | Bundle ID `com.jeremyhaber.Querywell`. Keychain service name is a separate constant `com.jeremyhaber.Querywell.secrets`. | Placeholder owner prefix; change before first public release (keychain service is decoupled so a bundle-ID change won't orphan secrets). |
| 3 | 2026-10-26 | Core package product named `QuerywellCore` (package dir `Packages/Core`). | Avoids clashing with generic `Core` module names in dependencies. |
| 4 | 2026-10-26 | **Swift Testing** for new tests (XCTest only where required by Xcode UI tests). | Modern, parallel, ships with Xcode 26 toolchain. |
| 5 | 2026-10-26 | Keychain: legacy file-based login keychain (`kSecClassGenericPassword`, no data-protection keychain). | Data-protection keychain needs a keychain-access-group entitlement + signing; that breaks `swift test`. Can migrate later. |
| 6 | 2026-10-26 | Connection metadata in a single `connections.json` (`schemaVersion: 1`) containing profiles + folders, written atomically. | Simple, human-inspectable; small data size. |
| 7 | 2026-10-26 | Local builds sign ad-hoc (`CODE_SIGN_IDENTITY=-`); hardened runtime ON; App Sandbox OFF. Developer ID signing deferred to `scripts/release.sh` (Phase 8). | Per brief; lets CI build without a team ID. |
| 8 | 2026-10-26 | Private GitHub repo `jeremyhaber/Querywell`, default branch `main`; push at end of each phase. | Jeremy approved creating the repo. |
| 9 | 2026-10-26 | Design canvas provided (see `design/DESIGN_NOTES.md`); snapshots committed under `design/project/`. Mockup web fonts (Inter/JetBrains Mono) map to SF Pro/SF Mono natively. | Canvas is the visual source of truth; native fonts per brief. |
| 10 | 2026-10-26 | `LM_SKIP_METADATA_EXTRACTION=YES` (project.yml + ci.sh command line). | Silences Xcode's AppIntents "metadata extraction skipped" noise warning, incl. on SwiftPM test bundles that ignore project settings. Remove if we ever adopt App Intents. |
| 11 | 2026-10-26 | `ConnectionRepository` mutations are transactional: applied to a copy, committed in memory only after the atomic disk write succeeds. Profile secrets are deleted *after* the profile is persisted as removed (orphaned secret is preferable to a profile missing its password). | Memory and disk never diverge on I/O failure. |
| 12 | 2026-10-26 | App Support dir created `0700`, `connections.json` `0600`. Production profiles require write confirmation but are not forced read-only (`readOnly` is a separate opt-in). | Least-privilege file perms; brief separates PROD guard from read-only mode. |
| 13 | 2026-10-26 | **SSH via system OpenSSH** (`/usr/bin/ssh -L`, password/passphrase via `SSH_ASKPASS_REQUIRE=force`) instead of Citadel, behind the `SSHTunnelProvider` protocol. | Brief allows the `ssh -L` fallback. System ssh natively handles 1Password/agent sockets, `~/.ssh/config` (ProxyJump, aliases), known_hosts verification, every key format; the same binary powers the Phase 7 terminal and remote mysqldump, so one SSH stack. Citadel can be added as a second provider later. |
| 14 | 2026-10-26 | Host keys: `StrictHostKeyChecking=accept-new` against the user's known_hosts (trust on first use); a *changed* key is a hard failure surfaced as `hostKeyMismatch`. | Matches Sequel Ace/ssh defaults without silently accepting MITM. |
| 15 | 2026-10-26 | Integration servers via `docker-compose.yml` on high ports (MySQL 8.4 :13306, MariaDB 11.4 :13307, Postgres 16 :15432 with TLS, Alpine sshd bastion :12222). Tests run only when `QUERYWELL_INTEGRATION=1` (set by `scripts/integration.sh`); SSH test keys generated per machine into `build/test-ssh/`, never committed. | Avoids clashing with local DBs; no private keys in git (GitHub push protection). |
| 16 | 2026-10-26 | Drivers use one shared NIO `EventLoopGroup` (`MultiThreadedEventLoopGroup.singleton`). Statements run one at a time per session; parallel work opens more sessions. | Mirrors a real client connection; avoids interleaving on one wire. |
| 17 | 2026-10-26 | Collation rewrite is a streaming DDL-only transform in Core (`CollationRewriter`), usable on both export and import; default "keep original". | Fixes cross-provider "Unknown collation" imports without risking data bytes; import-side fix covers dumps made elsewhere. |
| 18 | 2026-10-26 | "Batch update table type" interpreted as storage engine (`ENGINE=`); batch charset/collation conversion added alongside. Lives in the table browser (Phase 4). | MySQL historically called the engine "table type" (`TYPE=`). **Confirmed by Jeremy 2026-10-26.** |
| 19 | 2026-10-26 | Zero-warning gate applies to **our** code/config. `ci.sh` reports but doesn't fail on warnings unambiguously from SwiftPM checkouts (e.g. swift-nio's legacy `NIO`/`CNIOWindows` targets under Xcode 26's dependency scan). `swift build/test -Xswiftc -warnings-as-errors` still applies to all Core sources. | We can't fix upstream package manifests; failing on them would block every phase. Filter is narrow and covered by a classifier check. After #20 the clean build has 0 warnings; the filter is now a safety net. |
| 20 | 2026-10-26 | Core tests run via `swift test` only (not in the Xcode scheme); `QuerywellTests` reaches Core through the host app instead of linking it. | Linking the package in both app and test bundle forces dynamic package frameworks and caused a link-order race (Crypto). |
| 21 | 2026-10-26 | Known driver caveats: Postgres zero-row SELECTs re-run as `SELECT * FROM (…) LIMIT 0` to fetch columns (plain SELECT/WITH only); Postgres composite/geometric types arrive as bytes; MySQLNIO asserts on late pipeline errors in Debug builds. Revisit in Phase 5 (query editor). | Limits of MySQLNIO 1.9 / PostgresNIO 1.33 APIs; documented rather than hidden. |
| 22 | 2026-10-26 | Tunnelled connects race the driver handshake against ssh's "channel N: open failed" (tunnels log at `LogLevel=INFO`); tunnels retry on a fresh local port if ssh reports "Address already in use"; `LoopbackPort` never hands out the same port twice in quick succession. | Unreachable DB behind a bastion fails in <1s with ssh's real reason instead of a 15s timeout; concurrent window opens can't collide on ports. |
| 23 | 2026-10-26 | "Test connection" lives in Core (`ConnectionTester`, supports unsaved profiles via secret overlay); the button itself ships with the connection editor in Phase 3. | No connection editor UI exists yet. |
| 24 | 2026-10-26 | Tabs inside a connection window are an **in-window tab strip** (per design `Main.dc.html`), not NSWindow native tabbing. Native window tabbing is disabled for connection windows. | The design puts tabs under the connection header with per-kind dots; NSWindow tabs would duplicate the toolbar per tab and fight one-window-per-connection. |
| 25 | 2026-10-26 | Opening an already-open connection focuses its window by default; Settings → General can switch to "always new window" (and ⌥-Connect opens a second window). | Avoids accidental duplicate PROD sessions while still allowing two windows. |
| 26 | 2026-10-26 | Launcher filtering, ⌘K fuzzy ranking, tab state and the connection-editor draft live in Core as pure models; SwiftUI views stay thin. | Keeps UI logic unit-testable per ARCHITECTURE.md. |
| 27 | 2026-10-26 | Connection toolbar: identity and actions use `.automatic` placement with a `ToolbarSpacer(.flexible)` on macOS 26 (`.navigation`/`.primaryAction` on 14–15), the system title is removed (`.toolbar(removing: .title)` on 15+), and header density follows window width (engine label < 1040pt, quick-open text < 960pt). A snapshot test asserts no toolbar overflow at 1200/1000/820pt. | The stray glass circle Jeremy saw was AppKit's toolbar overflow button: `.navigation` items are width-capped on macOS 26 and the hidden title still took space. |
| 28 | 2026-10-26 | Snapshot harness (`scripts/snapshots.sh`) captures real window-server output of the app's own windows and waits with `await Task.sleep`, never `RunLoop.run`. | `cacheDisplay` mis-draws macOS 26 glass, and a blocking run loop starves the main actor so SwiftUI never finishes layout — both produced false artefacts. |
| 29 | 2026-10-26 | Table namespace = `TableRef(schema:name:)`: MySQL/MariaDB *database* or Postgres *schema* in the session's current database; switching Postgres databases reconnects the window. All generated SQL goes through `SQLDialect` (identifier/literal quoting); MySQL sessions strip `NO_BACKSLASH_ESCAPES` from the session `sql_mode` on connect so literal escaping is always valid. | One addressing model for both engine families; a single choke point for quoting prevents injection. |
| 30 | 2026-10-26 | Write guard: PROD writes always confirm (setting can't disable it); read-only beats PROD; unknown statements are write+destructive; `CALL`/`DO`/`EXECUTE` are destructive (opaque, no dry-run → typed DB name on PROD); dry-run counts only for single-table DELETE/UPDATE, otherwise "Can't estimate". Inline edits commit in one transaction with optimistic-concurrency WHERE on original values (floats/geometry excluded). | Conservative by default: a wrong "safe" classification on PROD is the expensive failure. |
| 31 | 2026-10-26 | Saved queries are stored per connection profile (or global) in `saved-queries.json`. Query history is per connection with bounded retention, defaults: 1,000 entries, 90 days, 2 MB per connection; statements over 64 KB stored truncated (open-only, not re-runnable); consecutive duplicates bump a run count. Deleting a connection purges its history and saved queries. Re-running from history goes through the normal runner + write guard. Limits are adjustable in Settings with a Clear History button. | Jeremy asked for saved queries on the profile and rerunnable history without unbounded local storage. |
| 32 | 2026-10-26 | `WriteOrigin.gridEdit`: on PROD, single-row PK-targeted UPDATEs from grid/inspector edits need a confirmation click with the exact SQL; grid DELETEs and any free-form UPDATE/DELETE still require typing the database name. | Typing the DB name for every cell edit would train users to type it reflexively, weakening the guard where it matters. |
| 33 | 2026-10-26 | Phase 4 UI: all writes go through `WriteGate` (App/Safety). Grid commits use `origin: .gridEdit`. ⌫ in the grid clears a cell (empty string for text columns, NULL otherwise); "Set to Default" only offers literal defaults (expression defaults like CURRENT_TIMESTAMP aren't evaluated client-side, except on inserted rows where the server fills them). After a conflict, "Reload, Keep My Edits" rebases each edit onto the fresh value (`EditSession.rebaseOriginal`). Pending edits survive sort/filter/paging; inserted rows show at the top of every page. | The server is the authority on defaults; a rebase is explicit so overwriting a colleague's change is a conscious choice. |
